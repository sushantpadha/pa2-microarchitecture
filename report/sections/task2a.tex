\task{2A}{Instruction-Conscious L2 Replacement Policy (I-RRIP)}

\subsection{Interface change}

{\sloppy We added a last parameter, \texttt{uint8\_t isInstruction}, to \texttt{update\_replacement\_state}: in the member-function pointer type in \texttt{inc/cache.h}, in every cache level's definition, and at every call site. Each call in \texttt{src/cache.cc} passes the \texttt{instruction} field of the packet it handles: the MSHR entry on a fill from the lower level, the write queue entry on a writeback that misses, and the read, write or prefetch queue entry on a hit. The BTB calls in \texttt{src/ooo\_cpu.cc} pass 0. The flag is also set on fills of page-table lines for instruction translations, so I-RRIP protects those lines too; the L2C instruction load MPKI does not count them, because it counts only load requests. I-RRIP stores the flag of each line when the line is filled, because \texttt{find\_victim} does not receive it.\par}

\subsection{Design: insertion, promotion, eviction}

An L1I miss stalls fetch stage itself. A data miss is often overlapped with independent work in the window. An L2 hit is therefore worth more for an instruction line than for a data line, and I-RRIP gives up some data hits to keep instruction lines. It starts from SRRIP with 2-bit RRPVs (maximum RRPV 3), which inserts every line at RRPV 2, promotes every hit to RRPV 0, and evicts the first line at RRPV 3, aging all lines until one reaches 3.

\textbf{Eviction rule.} Instruction lines age once per 4 aging rounds of data lines. Effectively, in a set that holds at least one data line, the victim search ends before any instruction line is aged. An instruction line is then evicted only if it already has RRPV 3, which it can reach only by aging while its set holds no data line.

\textbf{Experiments we ran.} \texttt{irrip.l2c\_repl} implements eight variants, which we call levels; the default is level 8, the final policy. Each level changes one rule of a previous one:

\begin{itemize}
  \item Level 1: data-first eviction, instruction lines aged every 2nd round, every line inserted at 2, instruction hit to 0, data hit RRPV $--$.
  \item Level 2: level 1, but instruction lines inserted at 0.
  \item Level 3: level 1, plus a cap of 6 instruction lines per 8-way set: when a set holds 6 or more, the instruction line with the highest RRPV is evicted.
  \item Level 4: level 2, but data hits promoted to 1. Level 5: level 1, but data hits promoted to 1.
  \item Level 6: level 1, but instruction lines aged every 4th round.
  \item Level 7: level 1, but data lines inserted at 3.
  \item Level 8: levels 6 and 7 together.
\end{itemize}

\textbf{Insertion.}
\begin{itemize}
  \item \emph{Instruction lines: not modified (RRPV 2).} Inserting them at 0 (level 2 vs.\ level 1) raises mean instruction MPKI by 11\% and mean data MPKI by 3\%, and lowers the speedup from 1.0182 to 1.0089. At RRPV 2, only instruction lines that are reused at the L2 get full protection. At RRPV 0, every instruction fill gets full protection, including lines that are not reused before they are evicted, and \textbf{data-first eviction} keeps them for a long time.
  \item \emph{Data lines: modified (RRPV 3).} Level 7 vs.\ level 1 lowers instruction MPKI by 8.6\% and raises data MPKI by 10\%, and the speedup rises from 1.0182 to 1.0216. A data line inserted at 3 is a victim candidate ahead of every instruction line unless it is hit first, so data that is not reused soon cannot push instruction lines out. A hit moves it to RRPV 2; it is still evicted before any instruction line once it ages back to 3.
\end{itemize}

\textbf{Promotion.}
\begin{itemize}
  \item \emph{Instruction hits: not modified (RRPV 0).} A hit is the only evidence of reuse, and RRPV 0 gives a reused instruction line the most protection which helps drastically based on the experiments.
  \item \emph{Data hits: modified (RRPV $-$ 1).} The data promotion rule barely matters (due to strong instruction protection in all subpolicies). We varied this but did not see considerable changes.
\end{itemize}

\textbf{Eviction.}
\begin{itemize}
  \item \emph{Modified: data first, instruction lines aged more slowly.} Aging instruction lines every 4th round instead of every 2nd (level 6 vs.\ level 1) lowers instruction MPKI by 3.1\% and raises data MPKI by 6.9\%, for a speedup of 1.0194 instead of 1.0182. This is evidence that keeping instructions in the L2C is more important than keeping data.
  \item On top of data insertion at 3, slower aging adds very little (level 8 vs.\ level 7): instruction MPKI falls by 0.8\%, data MPKI rises by 2.8\%, and the speedup is the same (1.0216). \textbf{We keep level 8 because it has the lowest instruction MPKI, which is the goal of this task.}
\end{itemize}

\textbf{The instruction cap -- odd results (level 3).} Level 3 has the highest speedup (1.0329), but its \textbf{instruction MPKI is 29\% above level} 1's, so it does not meet the goal of this task, and we did not choose it. The cap lowers LLC load misses (Table~\ref{tab:t2a-llc}): e.g. on Trace1, from 301.9k with level 1 to 267.4k, while L2C load misses rise from 447.4k to 464.5k. The reason we chose $6$ comes from a sweep where $6$ showed highest speedup.

I-RRIP lowers L2C instruction load MPKI on every trace: by 13\% on Trace1, 60\% on Trace2 and 40\% on Trace3. Data load MPKI rises on every trace, by 31\%, 37\% and 13\%. SRRIP alone is within 0.3\% of LRU on every trace, so the gain comes from the instruction priority, not from RRIP.

\textbf{Instruction misses cost more than data misses.} On Trace1, I-RRIP has 5\% \emph{more} L2C load misses than LRU (18.60 vs.\ 17.70 MPKI), yet its IPC is 0.7\% higher: it trades 1.35 MPKI of instruction misses for 2.26 MPKI of data misses. This is consistent with the standard argument.
